# ChronoBound

**Deployed:** [0xA090568E1a68800611D730C858A8747fc41AF893](https://explorer-studio.genlayer.com/address/0xA090568E1a68800611D730C858A8747fc41AF893) · [Live evidence](VALIDATION.md) · [Design](DESIGN.md)

A standalone GenLayer primitive for compiling explicit relative-time statements into **difference constraints with checkable certificates**. Builders can obtain a minute-resolution feasible schedule and tight event windows, or an explicit negative cycle explaining why the declared timing rules cannot all hold.

## Example

Assembly completes 30–60 minutes after the reference start. Release is exactly two hours after assembly and at most 200 minutes after the start. Consensus compiles the statements; deterministic code proves release can occur within minutes 150–180. Changing the last limit to 100 makes the network inconsistent. No model selects a schedule or decides whether a contradiction should be ignored.

## Consensus and mathematics

Each immutable rule names its from/to event indices and one original text. The semantic boundary derives inclusive `lower <= time[to] - time[from] <= upper` bounds in integer minutes. `null` means that side is unbounded. Validators independently recompile the original rules and compare every status, signed lower bound and signed upper bound. Explanations may differ. A malformed result aborts; an accepted UNCLEAR result sends the entire record to REVIEW. Source text is inserted by code, not generated by a model.

An upper bound creates edge `from → to` with that weight; a lower bound creates `to → from` with the negated weight. Event 0 is anchored at minute zero. Code adds `0 <= time[i] <= horizon` for every other event. Bellman–Ford produces either a feasible potential or a directed negative cycle. Negative-cycle edge indices, original rule references and summed negative weight are retained and checked. For feasible networks, all-pairs shortest paths derive each tight origin-relative range. The potential is normalized to event 0 and checked against every edge and horizon constraint.

A positive-duration dependency cycle is infeasible, while an ordinary dependency cycle with compatible zero/negative offsets can be feasible. This differs from merely rejecting cycles in a prerequisite graph. Range endpoints describe each event separately; selecting arbitrary points from all ranges is not guaranteed to produce a jointly feasible schedule. Use the returned `times` witness.

## State and calls

`SEALED → FEASIBLE → CERTIFIED`, or `SEALED → REVIEW | INCONSISTENT`.

| Method | Arguments | Permission |
| --- | --- | --- |
| `seal` | ident, payload | Caller creates immutable owner/ID namespace |
| `compile` | owner, ident | Anyone; SEALED only |
| `certify` | owner, ident, digest | Owner; FEASIBLE only; recomputes proof |
| `get_schedule` | owner, ident | Public JSON snapshot |
| `get_protocol` | none | `chronobound-1` |

`payload` has exactly `events`, `horizon`, `rules`. There are 2–5 distinct event descriptions (5–100 characters), horizon 1–10080 minutes, and 1–8 rules. Each rule has exactly `from`, `to`, `text`; indices must differ and texts are 20–600 characters. Payload length is 80–9000 characters. IDs use 1–40 ASCII letters/digits/underscore/hyphen. Text boundaries are trimmed on ingestion. Rules support exact whole-minute bounds and whole hours converted to minutes, with compiled values within ±10080. Calendars, strict inequalities, disjunctions, conditions and missing quantities require review.

The digest is SHA-256 of sorted compact Python JSON containing protocol, owner, ID, normalized plan, bounds and proof. Certification changes only the outer state and cannot alter the proof. It certifies feasibility of the accepted model compilation, not correctness of the prose or truth of an event.

See [examples/plan.json](examples/plan.json). Deploy the complete `contracts/chrono_bound.py` with no constructor arguments. With GenLayerJS, call `writeContract({address, functionName:'seal', args:[id, JSON.stringify(plan)], value:0n, leaderOnly:false})`, then `compile(owner,id)`. Read `get_schedule` using `TransactionHashVariant.LATEST_FINAL` and pass its digest to `certify`. The verification scripts provide complete calls without a frontend.

## Limits and trust

Inputs are the owner's public declarations; the contract does not authenticate outside authors, fetch events or monitor clocks. Event names must clearly identify the declared pair. Independent model executions can share mistakes, especially about direction, units or malicious instructions. Unsupported or ambiguous prose can stall certification. No edits, cancellation, payments, calendar dates, timezone handling, external action execution or administrator bypass. Use a fresh ID for corrected rules. This is a bounded scheduling primitive, not a general natural-language theorem prover or a guarantee that a real operation will finish on time.

## Run and verify

Node.js 22+ and Python 3.12+:

```sh
npm ci
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
genvm-lint check contracts/chrono_bound.py
python scripts/prepare-sdk.py
python sdk-tests/check_sdk.py
node scripts/read-live.mjs
```

The unit suite executes the actual source through a mocked host/model. Direct Mode exercises the pinned official SDK, storage and calldata with mocked model responses. Neither is live consensus. The final command performs only network reads: chain identity, exact source equality, signer/target/method/argument binding, full-consensus finalized receipts, state and deterministic proof checks.

The optional `NEW_TEST=1 node scripts/verify-live.mjs` performs a **new zero-value development deployment and writes**, not a routine read check. Do not run it to recreate already recorded evidence. It generates disposable signing accounts, saves private state outside this repository with restrictive permissions, journals intent before sending, saves hashes before polling, and resumes existing hashes without resending. If a send has an unknown outcome or a transaction fails, inspect it first. There is no automatic Appeal or blind resend. Never fund disposable test accounts; use your own wallet for continuing real integrations without exporting private keys.
