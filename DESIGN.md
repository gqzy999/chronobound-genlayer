# Design and adjacent mechanisms

The bounded repository review on 2026-10-29 covered the accessible repositories under gqzy999, chuanqili77, zuotu295, chongqianli7 and zsf11221, plus accessible public gqzy1 and halihalibt repositories. This is a mechanism comparison, not a worldwide novelty claim.

| Adjacent work | Existing core | ChronoBound distinction |
| --- | --- | --- |
| RunbookLatch / VOLTA | Prerequisite edges, cycles and execution order | Signed numerical difference bounds; Bellman–Ford feasibility, negative-weight cycle proof and tight relative windows |
| RatioRail | Rational unit equalities and conversion consistency | Additive temporal inequalities, one-sided bounds, origin/horizon constraints and schedule witnesses |
| BandPact | Intersection of two reports of one quantity | Multiple coupled event variables; feasibility is not pairwise interval overlap |
| ForkSeal | Semantic outcomes against a finite scenario regression suite | No expected outcomes or rule revisions; a mathematical constraint certificate is derived from the accepted compilation |
| AccordSpace | Finite-domain worlds, negotiation and owner relaxations | Continuous/integral difference-bound network, no plan enumeration or relaxation workflow |

The single nondeterministic boundary compiles meaning, direction and units. A validator independently regenerates every bound from the original input and agrees on stable fields only. All feasibility, proof, range and certification logic is deterministic. Keeping original normalized rule text beside each bound makes interpretation inspectable without trusting generated quotations.

Integer constants define a standard difference-constraint system. Feasible potentials are integral, so the returned witness meets the minute-resolution model. Tight per-event bounds are not independent choices. The horizon is an explicit part of the problem, and can itself cause inconsistency.

The API is intentionally immutable and bounded. Correcting a rule creates a fresh record. Public proof consumers must verify chain, source/protocol, finalized status and the full content digest before acting.
